# CS 255 – System Analysis and Design

# Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design?

The DriverPass project focused on designing a system for a client called DriverPass - a company that provides tools to help students prepare for DMV driving exams. The client requested a web-based system that would allow students to take online practice tests, schedule driving lessons, manage accounts, and access instructional content. The system was also designed to support administrative and instructional roles, allowing staff to manage users, lessons, and system data efficiently.


# What did you do particularly well?

I performed particularly well in gathering and organizing the client’s requirements into a clear and detailed business requirements document. I was then able to distinguish between functional and nonfunctional requirements and translate the client’s needs into specific system expectations. Additionally, I effectively used UML diagrams in the system design document to visually represent system processes and interactions, making the design easier to understand for both technical and nontechnical audiences.


# If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

If I could revise one part of my work, I would enhance the technical and architectural details of the system design document. I would improve this section by expanding on security considerations, scalability, and future system enhancements. Adding more detail in these areas would make the design more robust and better suited for real-world implementation.

# How did you interpret the user’s needs and implement them into your system design? Why is it so important to consider the user’s needs when designing?

I interpreted the user’s needs by closely analyzing the client interview transcript and identifying key challenges, such as limited access to practice exams and difficulty scheduling driving lessons. These needs were implemented into the system design through features like online testing, role-based access, and lesson scheduling. Considering user needs is critical because a system’s success depends on how effectively it solves real problems and provides a positive user experience.

# How do you approach designing software? What techniques or strategies would you use in the future to analyze and design a system?

I approach software design by starting with a clear understanding of requirements and then breaking the system into manageable components. I use techniques such as use case diagrams, activity diagrams, and class diagrams to model system behavior and structure. In the future, I would continue using iterative design, stakeholder feedback, and visual modeling tools to ensure systems meet both user needs and technical constraints.
